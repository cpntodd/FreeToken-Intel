## About

FreeToken is an edge-native Mixture-of-Experts (MoE) serving engine designed for running frontier-scale open-weight models on personal and consumer hardware. It treats heterogeneous edge resources—GPUs, CPUs, host memory, and interconnects—as a unified, elastic inference platform. Its core features include:  

- **Fast Edge-Native Runtime**: Provides efficient MoE serving with bandwidth-adaptive CPU–GPU co-execution ($q^\star$ policy), full-layer double-buffered prefill streaming, global LRU expert caching, graph-compatible execution, and the FTW fast weight format.  
- **Semantic-Aware Caching**: Features semantic anchor checkpoints for recurrent state and KV caches, allowing agentic context edits (e.g., tool calls, thinking blocks) to avoid redundant context recomputation.  
- **Elastic Memory Management**: Supports dynamic, runtime VRAM re-allocation between expert caches and KV memory without engine restarts or weight reloading.  
- **Broad MoE & Ecosystem Support**: Supports frontier open-weight MoE models (e.g., DeepSeek-V4-Flash, Qwen3.6-35B-A3B, GLM-5.2) across various parameter scales and quantization formats (e.g., MXFP4, NVFP4, FP8, BF16), with Anthropic/OpenAI-compatible APIs for seamless integration with real-world coding and tool-calling agents (e.g., Codex, Claude Code, OpenCode, OpenClaw, DeepSeek Harness). 
- **Diverse Consumer Hardware**: Scales across consumer laptops, gaming desktops, and workstation GPUs. Upstream supports NVIDIA RTX 30, RTX 40, and RTX 50 series GPUs; this fork is extending the same engine architecture to Intel Arc GPUs through PyTorch XPU/SYCL, OpenVINO, and Vulkan paths.

## Intel Arc support

The native Intel path preserves FreeToken's scheduler, model execution, KV cache,
sampling, and API layers. Selecting `--accelerator xpu` is explicit and does not
silently fall back to CPU or CUDA.

Current hardware-validated coverage on the Arc B580 includes:

- PyTorch XPU eager inference over oneAPI/Level Zero.
- End-to-end Gemma 4 and Llama 3 GGUF generation through the public `LLM` API.
- Intel-compatible Triton kernels for RMSNorm, RoPE, and activation operations.
- A bounded OpenVINO GPU compute-island prototype with separate transfer and inference
  timing and explicit rejection of CPU participation.
- A native Vulkan compute prototype that selects an Intel discrete GPU and rejects
  software Vulkan devices such as llvmpipe.

Work remains in progress for optimized native SYCL kernels, broader GGUF quantization
and model coverage, production OpenVINO interoperability, and production Vulkan compute
islands. See [Intel XPU development](docs/intel-xpu.md) for the validated software stack,
installation commands, known limitations, and B580 benchmark instructions.

## Getting Started

### Desktop app

Download FreeToken for Windows or Linux at [flashml.ai](https://www.flashml.ai/). It sets the engine up for you and gives you a GUI for running models, chatting, and tuning the engine.

### CLI

Install FreeToken with [uv](https://docs.astral.sh/uv/) (recommended) or pip:

```bash
uv pip install "freetoken[accel]"
```

Or build from source:

```bash
git clone https://github.com/FlashML-org/FreeToken.git && cd FreeToken
uv venv && source .venv/bin/activate
uv pip install -e ".[accel]"
```

For Intel Arc development, clone this fork and use its XPU-specific installation path:

```bash
git clone https://github.com/cpntodd/FreeToken-Intel.git
cd FreeToken-Intel
uv venv --python 3.12 .venv
```

Continue with the pinned Intel PyTorch, `triton-xpu`, and editable-install commands in
[docs/intel-xpu.md](docs/intel-xpu.md). The published upstream `freetoken[accel]`
package is CUDA-oriented and does not install this fork's Intel dependency set.
